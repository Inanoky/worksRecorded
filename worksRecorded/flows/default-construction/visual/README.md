# Limeni Visual

Limeni-only default-construction diary tab. The backend checks active user membership, project ownership, organization ID and flow on every upload, read and analysis request.

## Workflow

1. Choose a diary location and upload its base PDF through UploadThing.
2. Snapshot the non-archived diary records and their linked photos for that location. Other locations and unlinked gallery photos are not included.
3. Fetch the PDF once, then analyze all unfinished evidence images concurrently with `Promise.all`, one image per model request. Persist each outcome as it finishes. Reopening the view polls ongoing progress; resuming retries only unfinished/failed images, including after out-of-order completion.
4. Display suggested regions as independent coloured layers. Selecting a region reveals its diary source, image and alignment explanation.
5. Each normalized location has one active drawing. Uploading a replacement requires confirmation and archives prior versions. Concurrent uploads are serialized with a transaction-scoped advisory lock; replacement must reference the current drawing. “Atjaunot no žurnāla” reconciles current record/photo URL pairs for the selected location: removed sources lose their zones and progress, while newly linked images receive fresh IDs for analysis. Unchanged sources retain their snapshots, completed results and manual edits; the PDF and attempt history are preserved. No changes means no write or AI call; removal alone does not call AI. Updates reject active leases and use compare-and-swap protection. Gallery deletion removes linked diary URLs and their Visual evidence in one transaction, with drawing row locks and compare-and-swap protection. An active analysis of an affected drawing blocks deletion until it finishes. Successful deletion notifies the retained Visual view without reloading its PDF or changing location.
6. “Sākt analīzi no jauna” resets the selected drawing’s overlays and reruns the currently linked diary photos using the current model, so deleted images cannot return. It retains the PDF and attempt history. Confirmation is required.
7. “Dzēst rasējumu” permanently removes the selected Visual document and its analysis after confirmation. Older duplicates for that location are archived so they cannot reappear. Diary records, source photos and other locations remain unchanged. The uploaded PDF file is retained because other snapshots may share it. Delete/restart reject an active analysis lease and use compare-and-swap protection.
8. Select a zone, then “Pielāgot zonu” to drag corners, add corners at edge midpoints, or remove a focused corner with Delete. Arrow keys also move corners (Shift uses a larger step). Changes stay local until “Saglabāt zonu”; “Atcelt” restores saved geometry. Saved edits retain source linkage and record editor/time. Invalid, self-crossing or stale edits are rejected. Restarting analysis replaces manual edits after confirmation.
9. Hovering or focusing a zone highlights it without opening a popup. Clicking selects it and opens an image-first details panel sliding in from the right, with a full-width uncropped source photo, click-to-zoom, a collapsible description and work-type editor. Layer toggles and chronological “Zonu avoti” (oldest first, undated last) remain in a collapsible left sidebar. “Paslēpt visus / Rādīt visus” hides or shows every layer client-side; a mixed selection can be restored to all layers. The map-style viewport has floating zoom/fit controls, drag-to-pan, and 100–500% wheel zoom anchored at the cursor. The fitted 100% view is the minimum zoom for both wheel and button controls. A single GPU transform moves the PDF and zones together with a 180 ms eased animation; reduced-motion preferences disable animation. Wheel magnitude is normalized for trackpads and mouse wheels. Resizing the viewport preserves the viewed center. All navigation is client-side with no PDF refetch or AI call. Polygon fill opacity is 50%, 85% for the selected zone and 80% on hover or focus; selection keeps its contrasting outline after the pointer moves away.

## Storage and runtime

- The drawing uses a viewport-fitted CAD-style workspace: a compact location/actions toolbar, the full-width pannable PDF canvas and a slim cumulative-date bar. Layers and sources float over the canvas instead of resizing it. The left panel switches between layers and chronologically ordered sources, using height-aware pagination rather than nested scrollbars. Upload/replacement, restart, deletion and unlocated-image details live under “Rasējuma iestatījumi”. Long expanded details can scroll locally; normal drawing navigation has no scrollbars. Height is recalculated on window/parent resizing and when returning to the retained view, including enclosing bottom spacing. Resizing, panel toggles and source pagination do not refetch or remount the PDF.

- Limeni's diary is also retained in the shared project layout after its first authorized visit. The server route registers organization/user-scoped settings; other organizations and flows keep their existing rendering. Navigating back restores the diary without remounting, keeps filters/pagination and its image cache, and restores scroll. Project changes or browser reloads discard this memory. The server-selected Limeni mode avoids first loading a normal paginated diary before loading the Limeni snapshot. First-two-page image preloading continues but never blocks the retained diary table. Data older than 60 seconds refreshes in the background on return/focus and while visible; checks pause while the section/browser tab is hidden or records are being edited/saved. Failed checks retain existing data with a retry notice. Existing explicit refresh and post-mutation reloads remain in place.
- Izpildshēmas is a project navigation page at /dashboard/sites/{siteId}/izpildshemas. It loads lazily on its first visit and remains mounted, hidden, in the shared project layout when visiting Noliktava or other pages of the same project. Location, drawing, zoom, layer filters and date selection are retained without reloading the PDF. Returning to the view checks for new or changed sources without reanalyzing unchanged images. Progress polling pauses while hidden and resumes on return. Changing projects or reloading the browser resets this in-memory view.
- Analysis shows a spinner, analyzed/total/remaining counts, separate failure counts, and expandable per-image statuses with safe failure reasons. The progress bar counts settled images (successful or failed), not estimated AI progress. Upload and preparation have separate states. The browser polls saved progress every 1.5 seconds while the POST runs and when reopening a running analysis. Late polling responses cannot replace the final result. Zones appear as their results are saved.
- The date slider below the PDF shows cumulative zones through each calendar day, inclusive, using source diary dates in `Europe/Riga`. Slider changes and layer filters run entirely in the browser without AI calls or PDF reloads. Undated zones have an explicit opt-in when dated zones exist; if all dates are missing, all zones remain visible without inventing a date.

- Existing `Documents` records, type `limeni-visual-v1`. The PDF URL is in `url`; versioned state, evidence snapshots, output, attempts and token usage are in `description` as JSON.
- Updates use compare-and-swap on the previous description to avoid lost updates from concurrent requests. Model calls run concurrently; result writes are serialized using the latest saved version. Each generation retains its evidence ID, safe failure reason, response ID, output and token usage. Per-image progress is optional for legacy documents; their existing batch cursor is converted on resume. Restart clears per-image progress while retaining attempt history.
- Archived versions use document type `limeni-visual-v1-archived`. Existing legacy duplicates are collapsed to the newest in the index without read-time database writes; replacing/deleting that location archives the older versions.
- No database migration is required. Analysis does not change diary values. The selected-zone “Darba tips” editor explicitly updates the source diary record and recolors all its zones, retaining geometry and manual edits. It uses the project’s configured work types, organization/project/archive scoping, a source-revision check, serializable transaction and drawing compare-and-swap. Forma 2 work assignments are synchronized through the existing assignment path; failure there is reported separately from the successful record save. The retained diary is invalidated so it refreshes on return.
- Authenticated retrieval: `/api/sites/{siteId}/visual/{drawingId}`; PDF retrieval adds `?pdf=1`.
- Uses `gpt-6-sol` with `medium` reasoning, with optional `LIMENI_VISUAL_MODEL` override. Existing OpenAI credentials are reused; other AI flows are unchanged.
- PDF limit: 16 MB and 10 pages. Location limit: 200 linked evidence images. Inputs exceeding limits are rejected, never silently truncated.
- One model request per image, 150-second timeout, no automatic SDK retries. The API route allows 240 seconds. A processing lease is renewed on saved progress and becomes retryable after 210 seconds without updates. A model failure does not cancel other images; timeouts and rate limits are distinguished from PDF preparation failures.
- All pending model requests start in one server invocation, independently of browser polling. Closing the tab does not schedule or cancel subsequent batches. Platform termination can still interrupt unfinished requests; previously persisted image results are retained. Each request includes the base PDF, so total input usage can exceed the old multi-image batches; provider rate limits may require retrying failed images.

## Accuracy boundaries

While the selected drawing is visible, incremental synchronization runs on opening/return, browser focus and every 30 seconds. Checks pause while hidden or editing and do not overlap. Cached drawing, zoom, date and layer selections stay visible. New/changed unedited sources are analyzed; unchanged sources never call AI. Failed updates retain their last valid polygons, labelled as previous results. Successful reanalysis replaces only that source’s polygons. Changed manually adjusted sources retain their geometry and are flagged for review, with “Paturēt zonu” and “Analizēt vēlreiz” choices. Source deletion still removes its zones immediately. “Atjaunot no žurnāla” remains available as a manual check.

Clicking a zone renders it above other overlays with 85% fill and a persistent contrasting 4px outline, independent of hover. Its source and work-type editor appear in the right-side panel without resizing or reloading the drawing. Clicking empty map space or closing the panel clears selection, except while geometry or work-type edits are unsaved. Progress polling pauses when the view is hidden; an already started server analysis can still finish and persist results.

The source sketch identifies the intended work area; the target structural PDF supplies its clean geometry. The prompt asks for straightened, plan-aligned boundaries rather than pixel-perfect ink tracing: wobbly room outlines become clean room polygons, and corridor strokes become corridor-shaped zones. It preserves partial-room coverage, openings, exclusions, visible crop limits and genuine angled/curved structural geometry.

The feature is designed primarily for marked-up floor plans. Once the drawing is aligned, the model makes a best-effort approximation from stripes, hatching, overlapping strokes, open outlines and cropped annotations, using walls and room geometry to interpret edges. Ambiguous attribution is resolved using diary context and explained in the result. It does not infer completed floor area from quantities, provide verified measurements or calculate completion percentages. Geometry must reference known evidence, a valid PDF page, two distinct alignment anchors and a valid normalized simple polygon. There is no numeric confidence cutoff. Colour is derived from the diary work name, not model-selected image colour.

Confidence is a model estimate, not a guarantee. All overlays are explicitly labelled approximate and require review. Unrelated drawings, unalignable plans, unmarked delivery photos and explicitly planned-only work still remain unlocated. Rough or ambiguous annotation boundaries alone must not cause rejection. If none can be located, the UI shows “Nevar atrast darbus”. Existing results are unchanged until the user selects “Sākt analīzi no jauna”.

## Verification

`node scripts/preview-limeni-visual.mjs` serves the actual Visual components at `http://127.0.0.1:4318` using synthetic diary records and a generated PDF. Server actions and upload hooks are replaced in-memory; the preview never connects to the production database or AI. This supports browser checks for zoom, panning, editing and responsive layout without authentication or production writes.

Mocked tests cover organization/project scope, selected-location snapshots, concurrent writes, retry/resume, model-output validation, unsafe PDF URLs, PDF size/page limits, rendering, layer toggles and uploads. No real model or production database is called by these tests.

Before rollout, verify with a real Limeni base drawing and its marked-up diary images, including a rotated crop, a different floor and an unrelated building. Review every proposed region against the source; this quality calibration is not replaced by the unit tests.
